# adopt

A go_router app **half-way through adopting fespalier**. The hand-written routes nobody has moved
are still there (`/` and `/legacy/orders/:id`). The products pages come from fespalier's tree,
mounted under `/shop`. The old product URLs (`/products`, `/products/:id`) redirect to the typed
routes that replaced them. `startup.dart` has the 0.12 move of a hand-written `main()` into
`ready()` and `attach()`.

It is the example for the [`fespalier-migration`](../../skills/fespalier-migration/SKILL.md) skill
(its adoption page is
[`references/go-router-adoption.md`](../../skills/fespalier-migration/references/go-router-adoption.md);
the docs are [Migration](../../docs/migration.md#adopting-fespalier-in-a-go_router-app) and
[`main()`](../../docs/app-startup.md)).

## What it shows

Two screens, a products list and a product, in two apps that open the same URLs:

| URL                | Before (`lib/before/`) | Now                                              |
| ------------------ | ---------------------- | ------------------------------------------------ |
| `/`                | legacy home            | the same code, unmoved                           |
| `/legacy/orders/7` | legacy order           | the same code, unmoved                           |
| `/products`        | go_router route        | redirects to `/shop` (`ProductsRoute`)           |
| `/products/2`      | go_router route        | redirects to `/shop/products/2` (`ProductRoute`) |
| `/products/abc`    | not found              | not found (no redirect: there is no product)     |
| `/products/99`     | the failure screen     | the failure screen, from `error.dart`            |

```text
lib/
  main.dart                       Future<void> main() => AppMain.run();
  screens.dart                    the screens, plain widgets; before and now both draw these
  shop.dart                       a pretend backend and the providers (not fespalier)
  legacy_routes.dart              the hand-written routes nobody has moved (spread into both routers)
  router.dart                     buildRouter(): legacy routes + redirects + AppRoutes.mount(at: '/shop')
  boot_log.dart                   what ran in which order (the startup test reads it)
  before/
    router_before.dart            the app before: one GoRouter with every route, pages that load their own data
    main_before.dart              the 0.11-style main(): its own ProviderContainer, then a post-frame step
  app/                            fespalier's tree, mounted under /shop
    app.dart                      App, and router(): returns buildRouter() (the half-moved router)
    startup.dart                  ready(container) and attach(router, container)   (since 0.12.0)
    page.dart, data.dart          /shop              the list; data.dart selects the catalog provider
    products/$id/                 /shop/products/2   page, data (selector), loading, error
    not_found.dart                what the host router's errorBuilder forwards to
  app.g.dart, app.main.g.dart     generated by `fsp gen`, committed
test/
  parity_test.dart                the same URLs open the same screens before and now
  mount_test.dart                 legacy + mounted routes, redirects, typed routes from a legacy page
  startup_test.dart               ready() before the router, attach() after, through AppMain.root()
```

Two things this example settles that the docs only hint at:

- **`main: auto` and a router of your own work together.** `app.dart`'s `router()` does not have to
  return `AppRoutes.router()`: `fsp` reads its signature (`GoRouter router()`, no parameters) and not
  its body. Here it returns a `GoRouter` with `...AppRoutes.mount(at: '/shop', navigatorKey: rootKey)`
  among its routes, and `ready()` and `attach()` in `startup.dart` still run around it, in the order
  `ready()`, the router, `attach()`. So an adopting app does not need `main: manual` (which reads
  neither file) to mount.
- **Without adapters or telemetry there is nothing else to pass on.** `AppMain.routerObservers()` and
  `launch: AppMain.launch` exist only with `adapters:`; add them to your `GoRouter(...)` then.

## Steps (the same as the skill's adoption page)

1. **Install** `fespalier` and `fsp`, run `fsp init` (it never overwrites a file), and delete the
   starter files you do not want. A `layout.dart` wraps everything below it.
2. **Mount it** inside your router, under a prefix, with your router's own `navigatorKey`
   ([`lib/router.dart`](lib/router.dart)). Send unknown URLs to `AppRoutes.notFound(state.uri)`.
3. **Move one route at a time**: `products/:id` became the folder
   [`lib/app/products/$id/`](lib/app/products/$id) (`page.dart` with the typed `product`, `data.dart`
   a selector for the provider you already had, `loading.dart`, `error.dart`). The old page is still
   in [`lib/before/router_before.dart`](lib/before/router_before.dart) to compare.
4. **Keep the old URLs**: a `GoRoute` with a `redirect` to the typed route's `.location`
   ([`_movedUrls`](lib/router.dart)). Legacy code that navigates by string is forwarded; move it to
   typed routes (`ProductRoute(id: 2).go(context)`) when you get to it.
5. **Move `main()`** (a hand-written one) over: the overrides to `startup()`, the code between creating
   the `ProviderContainer` and `runApp` to `ready()`, the post-frame step that needs the router to
   `attach()` ([`startup.dart`](lib/app/startup.dart) here,
   [`main_before.dart`](lib/before/main_before.dart) for the original), and `lib/main.dart` becomes
   `AppMain.run()`.
6. **Test**: `pumpRouter` works with your own `GoRouter`; build a new router per test. `AppMain.root()`
   runs `ready()` and `attach()`; `pumpRouter` does not.
7. **Commit `lib/app.g.dart`** and run `fsp check` in CI, plus the stale-file diff
   (`dart run fespalier gen`, `git diff --exit-code lib/app.g.dart`).

When every route has moved: mount at `/` (`AppRoutes.mount()`) or return `AppRoutes.router()` from
`router()`, delete `lib/before/`, `lib/legacy_routes.dart` and `test/parity_test.dart`.

## Run it

```sh
flutter pub get
flutter run
```

Things to try: tap **All products** on the home page and watch the URL become `/shop`; open
`/products/2` (on the web, `flutter run -d chrome` and the address bar) and it lands on
`/shop/products/2`; `/products/abc` and `/nope` are not found.

## Test it

```sh
flutter analyze
dart format --set-exit-if-changed .
flutter test
```

[`parity_test.dart`](test/parity_test.dart) is the one that keeps the migration honest: each row is
an old URL, the screen it opens, and where the half-moved app ends up. Add a row when you move a
route; delete the file with `lib/before/`.
