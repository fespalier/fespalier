# minimal

The smallest real fespalier app. It is what you get from `flutter create` and `fsp init`, plus
a few pages. Read this one first; [`shop`](../shop), [`features`](../features) and
[`tabs`](../tabs) go further.

```
lib/
  main.dart                     runApp(… AppRoutes.router() …)
  items.dart                    a pretend backend (not fespalier)
  app.g.dart                    generated by `fsp`, committed
  app/
    layout.dart                 AppLayout({required Widget child})     an AppBar around every page
    page.dart                   HomePage()                             /
    not_found.dart              NotFoundPage({required Uri uri})       /nope, /items/abc
    transition.dart             transition(key, child)                 how routes animate
    about/
      page.dart                 Widget page()                          /about   (a function page)
    items/$id/
      page.dart                 ItemPage({item, qty})                  /items/2?qty=3
      data.dart                 Future<Item> data(Ref ref, {required int id})
      loading.dart              ItemLoading()                          while data.dart runs
      error.dart                ItemError({id, error, retry})          when data.dart throws
test/app_test.dart              widget tests
```

## How it was made

1. **Create the app.** `--empty` gives a bare `lib/main.dart`. (This repo keeps no platform
   folders in its examples, so they were deleted; in your own app, keep them.)

   ```sh
   flutter create --empty --project-name minimal minimal
   cd minimal
   ```

2. **Add the package** to `pubspec.yaml` (here a path dependency, since the example lives in
   the repo; in an app it is a `git:` dependency, see
   [Getting started](../../README.md#getting-started)), then `flutter pub get`. The
   `flutter_lints` line was already there: `flutter create` adds it, and
   `analysis_options.yaml` includes it.

   ```yaml
   dependencies:
     fespalier:
       path: ../../packages/fespalier
   ```

3. **Run `fsp init`.** It writes `lib/app/layout.dart`, `page.dart`, `not_found.dart` and
   `transition.dart`, and the first `lib/app.g.dart`, and prints what is left to do. It never
   overwrites a file, so it is safe to run twice.

   ```sh
   fsp init
   dart format .     # init's files are not formatted the way `dart format` likes them
   ```

4. **Replace `lib/main.dart`** with the one `fsp init` printed (this one adds a title and a
   theme). `AppRoutes.router()` is the whole router, generated from the folder.

5. **Write the pages.** Each file below says what it is by its name, and what it needs by its
   constructor. Open them: the comments explain each one.

   | File | What it does |
   |---|---|
   | [`app/layout.dart`](lib/app/layout.dart) | Wraps every page in a `Scaffold` with an `AppBar`. It asks for `child`, so it is a layout. |
   | [`app/page.dart`](lib/app/page.dart) | The page at `/`: a **class** page. It links to the others with typed routes. |
   | [`app/about/page.dart`](lib/app/about/page.dart) | The page at `/about`: a **function** page, `Widget page()`. The folder is the URL. |
   | [`app/items/$id/page.dart`](lib/app/items/$id/page.dart) | The page at `/items/<id>`. `$id` makes a segment; `item` is filled with what `data.dart` returns; `qty` (optional) is the query parameter `?qty=`. |
   | [`app/items/$id/data.dart`](lib/app/items/$id/data.dart) | Loads the item. `required int id` makes `$id` an `int` everywhere, so `/items/abc` is not found. |
   | [`app/items/$id/loading.dart`](lib/app/items/$id/loading.dart) | Shown while `data.dart` runs. |
   | [`app/items/$id/error.dart`](lib/app/items/$id/error.dart) | Shown when `data.dart` throws, with a **Retry** button (`retry`). |
   | [`app/not_found.dart`](lib/app/not_found.dart) | Shown for a URL nothing matches. It is optional; without it you get a plain "Nothing at /path". |
   | [`app/transition.dart`](lib/app/transition.dart) | `fsp init` wrote it: every route animates with Material's transition (see [the note](../../README.md#getting-started) on go_router 18). |
   | [`pubspec.yaml`](pubspec.yaml) | The `fespalier:` section is optional config for `fsp`. Here: `format: true` and `data_retry: none`. |

6. **Generate.** `fsp gen` reads the tree and writes [`lib/app.g.dart`](lib/app.g.dart),
   which has `HomeRoute`, `AboutRoute` and `ItemRoute(id:, qty:)`. It is committed, so the
   app builds without `fsp`. Leave `fsp watch` running next to `flutter run` and it regenerates
   on every save; `fsp check` only checks, and is what CI runs.

   ```sh
   fsp gen
   ```

## Run it

```sh
flutter pub get
flutter run
```

Things to try: tap through the home page; open `/items/2?qty=3` (on the web, after
`flutter run -d chrome`, put it in the address bar); `/items/99` shows `error.dart`;
`/items/abc` and `/nope` show `not_found.dart`.

## Test it

```sh
flutter analyze
dart format --set-exit-if-changed .
flutter test
```

[`test/app_test.dart`](test/app_test.dart) uses `pumpRouter` from `package:fespalier/testing.dart`
to boot the generated router at any location. It covers tapping through the layout, a deep
link with a segment and a query parameter, not-found for an unknown path and an unparsable
segment, `loading.dart` then the data, `error.dart`, and a typed `ItemRoute(...).go(context)`.
See [Testing](../../README.md#testing).
