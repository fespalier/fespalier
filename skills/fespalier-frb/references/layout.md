# The layout, file by file

The tree in [`SKILL.md`](../SKILL.md#the-layout), with what each file holds and its skeleton. Names follow
[`examples/frb-cose`](../../../examples/frb-cose/README.md); a new app renames `NotesCore` and keeps the rest. The Dart
blocks are sketches (they name generated bindings), so `just skill-samples` does not build them.

## The project root

**`pubspec.yaml`.** The runtime and, with native assets, the hooks package, both at the codegen's exact version (no
caret: the generated code checks it):

```yaml
environment:
  sdk: ^3.10.0 # build hooks 2.x; raise it for what else you depend on (frb-cose claims ^3.12.0 for fespalier_keypair)
  flutter: ">=3.44.0" # frb-cose's floor, the one CI runs this layout on (3.47.7)

dependencies:
  flutter_rust_bridge: 2.13.0
  flutter_rust_bridge_hooks: 2.13.0 # native assets only; Cargokit has `rust_lib_my_app: {path: rust_builder}` instead
  fespalier_frb: # the change feed and initRustCore, at the same url and ref as fespalier
```

Write the comment that lists every place the version is pinned, next to the pin, so the next person bumps all of them.

**`flutter_rust_bridge.yaml`.** What the codegen reads; run `flutter_rust_bridge_codegen generate` in the root:

```yaml
rust_input: crate::api # only api/ is the surface
rust_root: rust/
rust_output: rust/src/frb_generated.rs
dart_output: lib/src/rust
auto_upgrade_dependency: false # the pins are yours, not the codegen's
web: true # the bindings still compile for a web build that never calls them
build_runner: false # no freezed: the surface has no enum with data
```

**`hook/build.dart`** (native assets). Built for every `flutter test`, `run` and `build`:

```dart
// sketch: hook/build.dart
import 'package:flutter_rust_bridge_hooks/flutter_rust_bridge_hooks.dart';

void main(List<String> args) async {
  await build(args, (input, output) async {
    await const FlutterRustBridgeNativeAssetsBuilder(cratePath: 'rust').run(input: input, output: output);
  });
}
```

With Cargokit, `rust_builder/` replaces it ([build-integration](build-integration.md)).

**`analysis_options.yaml`.** Exclude nothing generated by hand: the generated Dart carries its own `ignore_for_file`.
`dart format` skips nothing either, so format after `flutter pub get` (the generator formats by the package's language
version).

## `rust/`

**`Cargo.toml`.** The three crate types (the hook links `cdylib` or `staticlib`, whichever the platform needs; `rlib`
serves `cargo test` and `tests/`), FRB exact, and the lints of the generated `cfg`:

```toml
[lib]
crate-type = ["cdylib", "staticlib", "rlib"]

[dependencies]
flutter_rust_bridge = "=2.13.0"
tokio = { version = "1", features = ["rt", "sync", "time"] } # a timeout around a Dart callback

[lints.rust]
unsafe_code = "deny"                                                        # the generated module alone allows it
unexpected_cfgs = { level = "warn", check-cfg = ['cfg(frb_expand)'] }       # the codegen expands with --cfg frb_expand
```

**`Cargo.lock`** is committed: it is an application's lockfile, and an exact `=x.y.z` on a facade crate pins only the
facade, not what it depends on (frb-cose's CrateStack crates are kept equal across lockfiles by a test).

**`rust-toolchain.toml`.** An exact channel (never `stable`), the components CI runs, and **every target** the app is
built for. The native-assets hook refuses a triple the file does not list, and rustup installs every listed target the
first time (frb-cose's twelve are about 2 GB once per machine):

```toml
[toolchain]
channel = "1.98.1"
components = ["rustfmt", "clippy"]
profile = "minimal"
targets = [
  "aarch64-linux-android", "armv7-linux-androideabi", "x86_64-linux-android",
  "aarch64-apple-ios", "aarch64-apple-ios-sim", "x86_64-apple-ios",
  "aarch64-apple-darwin", "x86_64-apple-darwin",
  "x86_64-unknown-linux-gnu", "aarch64-unknown-linux-gnu",
  "x86_64-pc-windows-msvc", "aarch64-pc-windows-msvc",
]
```

**`src/lib.rs`.** The two layers, and the generated module fenced off:

```rust
pub mod api;
pub mod core;

// Generated by flutter_rust_bridge_codegen and checked against it in CI: never formatted or edited by hand.
#[rustfmt::skip]
#[allow(unsafe_code, clippy::pedantic, clippy::unwrap_used, clippy::expect_used, reason = "generated")]
mod frb_generated;
```

**`src/core/`.** The engine, one module per concern (frb-cose: `client`, `signer`, `registrar`, `journal`, `events`,
`error`), each with its `*_tests.rs` beside it. It names no FRB type: the callback is a type alias of its own
(`type SignFn = Arc<dyn Fn(Vec<u8>) -> SignFuture + Send + Sync>`), which FRB's `DartFnFuture` happens to fill.
Errors are an `enum Error` with fixed `Display` texts.

**`src/api/`.** `mod.rs` lists the files; each file is structs, fieldless enums, one opaque `pub struct` with an
`impl` block, and the `From` conversions from the engine's types. See [bridge-surface](bridge-surface.md).

**`tests/`.** The engine against a server in process (frb-cose: `against_server.rs` drives the example's own server
crate, a dev dependency by path) and contract tests (`contracts.rs`: the ops the core accepts are the server's).

**`deny.toml`.** `cargo deny check` for licences and advisories, as for any Rust you ship.

## `lib/`

**`lib/app/`** is the fespalier tree and nothing in it imports `lib/src/rust/`. `startup.dart`:

```dart
// sketch: lib/app/startup.dart
Future<List<Override>> startup() async {
  if (kIsWeb) return unavailableOverrides(); // before anything names the bindings
  final config = CoreSettings.fromEnvironment(); // fallible work before the init: init cannot run twice
  await initRustCore(loadCore); // fespalier_frb: one span, rethrows for splash.dart
  final core = await openCore(config: config); // frb_core.dart
  return coreOverrides(core: core);
}
```

**`lib/src/core.dart`.** The seam: the interface, the plain data types re-exported from the bindings (so the rest of the
app imports this file and not `rust/`), the fallback core and the provider that throws until overridden:

```dart
// sketch: lib/src/core.dart
export 'rust/api/core.dart' show CoreAnswer, CoreError, CoreErrorKind, CoreEvent, CoreEventKind;

abstract interface class Core {
  bool get available;
  Future<CoreAnswer> call({required String op, required String argsJson});
  Stream<CoreEvent> changes();
}

final class UnavailableCore implements Core {
  const UnavailableCore();
  @override
  bool get available => false;
  @override
  Future<CoreAnswer> call({required String op, required String argsJson}) => Future.error(
    const CoreError(kind: CoreErrorKind.transport, message: 'the Rust core is not in this build'),
  );
  @override
  Stream<CoreEvent> changes() => const Stream.empty();
}

final coreProvider = Provider<Core>(
  (ref) => throw UnimplementedError('Override coreProvider (startup.dart does; a test passes a fake).'),
);
```

**`lib/src/frb_core.dart`.** The only file that calls `RustLib.init` and the generated opaque object's constructor, and
the only place a Dart callback is handed to Rust:

```dart
// sketch: lib/src/frb_core.dart
Future<void> loadCore() => RustLib.init();

Future<Core> openCore({required rust.CoreConfig config, required KeypairSigner signer}) async =>
    FrbCore(await rust.NotesCore.open(config: config, sign: (bytes) => _sign(signer, bytes)));

Future<Uint8List?> _sign(KeypairSigner signer, Uint8List bytes) async {
  try {
    return await signer.sign(bytes);
  } on Object {
    return null; // a throw here would panic the generated Rust code
  }
}
```

**`lib/src/changes.dart`.** One feed per core stream, opened once per container:

```dart
// sketch: lib/src/changes.dart
final coreChanges = ChangeFeed<CoreEvent>((ref) => ref.watch(coreProvider).changes(), name: 'my_app.core');
```

**`lib/src/wiring.dart`.** `coreOverrides(...)` and `unavailableOverrides()`: the lists `startup()` returns, so a test
builds the same list over a fake and the wiring is tested too. A `CrateStackTransport` over the core, the account scope
and the like go here ([cratestack-embedded](cratestack-embedded.md)).

**`lib/src/rust/`** is generated: `api/<file>.dart` per `api/` file, `frb_generated.dart`, `.io.dart` and `.web.dart`.

## `test/`, `server/` and the commands

See [testing](testing.md). A server the core talks to lives in `server/` as a standalone crate with its own
`Cargo.lock` and `rust-toolchain.toml` (the same channel as `rust/`), so its build never moves the core's lockfile.

The commands an app wants, whatever runs them (`just`, `make` or `fespalier: tasks:`):

| Command  | Runs                                                                                                                                                                              |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| core     | in `rust/`: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`, `cargo build --locked`, `cargo deny check`                                            |
| bindings | `flutter pub get`, the pinned `flutter_rust_bridge_codegen generate`, then `git diff --exit-code -- lib/src/rust rust/src/frb_generated.rs` and a check for untracked files there |
| app      | `dart format --set-exit-if-changed .`, `flutter analyze`, `flutter test`                                                                                                          |
| e2e      | the server built, then `flutter test` with the variable that names it and the one that makes the test required                                                                    |

The bindings command checks the codegen's version first (`flutter_rust_bridge_codegen --version`) and refuses another:
a different codegen writes different files, and the diff would blame the wrong change.
