# Diagnostics: `fsp add` and `fsp upgrade --app` (since 0.23.0)

As of 0.23.0 (`cli/src/add.rs` for the steps of `fsp add`, `cli/src/add/plan.rs` for its checks,
`cli/src/upgrade_app.rs` for `fsp upgrade --app`, `cli/src/pins.rs` for how both read the pins and
`cli/src/pubspec_edit.rs` for the pubspec edits). Messages are quoted as they are printed, to stderr, exit 1,
unless noted. The user documentation is [fsp add](https://github.com/fespalier/fespalier/blob/main/docs/cli.md#fsp-add) and
[Moving the app's pins](https://github.com/fespalier/fespalier/blob/main/docs/cli.md#moving-the-apps-pins); the commands
are in `fespalier`, `references/cli-and-config.md`.

Both commands check everything before they write anything: a refusal leaves the app as it was.

## `fsp add`: before anything is written

`{x}` is a value you gave, `{ids}` the features of `fsp create --list-features`.

| Message                                                                                                                                                                                                                   | Cause and fix                                                                                                                                                                                                                                                                                                          |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ``fsp add needs a feature: {ids} (`fsp create --list-features` says what each adds)``                                                                                                                                     | No feature on the command line. Name one or more.                                                                                                                                                                                                                                                                      |
| `` `all` is for `fsp create`; fsp add takes features by name: {ids} ``                                                                                                                                                    | `all` makes a new app with every feature. Name the features you want.                                                                                                                                                                                                                                                  |
| ``unknown feature `{x}`; the features are {ids} (`fsp create --list-features` says what each adds)``                                                                                                                      | A misspelled id.                                                                                                                                                                                                                                                                                                       |
| `` `adaptive` takes the place of lib/app/layout.dart, lib/app/page.dart, lib/app/about/page.dart, which are the app's own: only `fsp create` makes it (`fsp create --template tabs`) ``                                   | The tabs template replaces the base app's root layout and pages. For an app you have, add `fespalier_adaptive` and its layout by hand (docs/layouts.md, "A bar, a rail or a drawer").                                                                                                                                  |
| ``fsp add wires a feature into the generated main() (lib/app/startup.dart, lib/app/app.dart), and this app has `main: manual`; add it by hand: docs/cli.md, "fsp create", says what each feature adds``                   | With `main: manual`, `startup.dart` and `app.dart` are not read. Wire the feature in your own `main()`; `fsp add <feature> --dry-run` on a copy with `main: auto` shows the lines.                                                                                                                                     |
| ``fsp add writes the files of `fsp create`, which are in lib/app/ and import lib/app.g.dart, and this app sets `app_dir:` or `output:`; add the feature by hand: docs/cli.md, "fsp create", says what each feature adds`` | The feature's files would not compile in another folder. Add it by hand.                                                                                                                                                                                                                                               |
| ``pubspec.yaml does not list fespalier under dependencies: (`fsp init` says what to add)``                                                                                                                                | The app does not depend on fespalier yet (the same for `fsp upgrade --app`). Add it as `fsp init` prints, or use `fsp create` for a new app.                                                                                                                                                                           |
| `fespalier comes from {what}; fsp reads a git dependency (url:, path: packages/fespalier, ref:) or a path: to a checkout's packages/fespalier`                                                                            | `fespalier` is a version range (it is on no registry), or a git dependency without `path:` or `ref:` (the same for `fsp upgrade --app`). Write it as the README shows.                                                                                                                                                 |
| `fsp add pins a new package as fespalier is ({how}), and these are pinned otherwise:` then one line per package, then ``Pin them as fespalier is (`fsp upgrade --app` moves refs together), then run fsp add again``      | A companion under `dependencies:` or `dev_dependencies:` has another `url`, `ref` or folder than `fespalier`. pub would refuse the mix anyway; `fsp upgrade --app` moves every ref of one repository to one release.                                                                                                   |
| ``fsp add writes the files of `fsp create`, which are Dart 3.9 (`sdk: ^3.9.0`), and pubspec.yaml allows Dart {v} (`environment: sdk:`); raise that to ^3.9.0 first (Flutter 3.35 comes with Dart 3.9)``                   | The files use Dart 3.9 (wildcard parameters need 3.7) and are formatted for it. fespalier needs Flutter 3.35, which has Dart 3.9, so raising the bound costs nothing; `dart format` may then change your own files.                                                                                                    |
| `` `{id}` needs Flutter {f} or newer, and pubspec.yaml allows Flutter {v} (`environment: flutter:`); raise that first ``                                                                                                  | A feature above the app's declared floor. Raise `environment: flutter:`.                                                                                                                                                                                                                                               |
| `` `{a}` and `{b}` cannot be combined `` / `` `{a}` and `{b}` cannot be combined, and the app has `{b}` ``                                                                                                                | Two features whose recipes conflict (none does in 0.23.0).                                                                                                                                                                                                                                                             |
| `` `{id}` writes {files}, and {some} is there already; fsp add never writes over a file. Move it, or add the feature by hand: docs/cli.md, "fsp create", says what it adds ``                                             | One of the feature's own files is there (`lib/app/contact/page.dart` for `forms`). Rename or move yours; a feature whose files are **all** there is not refused (its files are kept).                                                                                                                                  |
| `could not edit pubspec.yaml safely ({why}), so nothing was written. Make this change by hand, then run fsp add again:` then the lines                                                                                    | A layout the line editor does not edit: `` `dev_dependencies:` is written on one line; fsp adds keys to a block mapping `` (a flow mapping), `is laid out in a way fsp does not edit` (the result would read differently), `is not a list fsp can add to`. Write the lines, then run it again: it skips what is there. |
| `the pubspec.yaml fsp add would write does not check: {why}`                                                                                                                                                              | The edit is right but the `fespalier:` section then breaks a rule of `fsp gen` (`otel: true` with `main: manual`, say). Fix the key it names.                                                                                                                                                                          |
| ``note: `{id}` is in the app already`` then `nothing to add` (exit 0)                                                                                                                                                     | Not an error: the feature's packages, keys and files are all there.                                                                                                                                                                                                                                                    |
| `note: kept {name}: {yours} (the feature asks for {range})`                                                                                                                                                               | Not an error: your constraint on a dependency the feature needs is kept. pub resolves it with the companion's own constraint; raise yours if pub cannot.                                                                                                                                                               |
| `note: {name} is under dev_dependencies:, and the feature needs it under dependencies: move it there`                                                                                                                     | The feature imports it from `lib/`. Move the line.                                                                                                                                                                                                                                                                     |

| ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `By hand: {file} (it is not what fsp create writes for the features the app has, so it is yours). Make this change:` then lines | Not an error (exit 0): a shared file you changed (`lib/app/startup.dart`, `lib/app/app.dart`, `test/routes/setup.dart`, another feature's test) was left as it is. Apply the `+` and `-` lines to it; until then the feature is not wired in (`Until the changes above are made, the feature is not wired in, and its test fails.`). |
| `By hand: {file} (it is not there, though the features the app has would have written it). ## `fsp upgrade --app`

`--check` exits 3 (not 1) when a ref would move. With `--json` the object is on stdout and every line below on stderr.

| Message                                                                                                                                                                                                 | Cause and fix                                                                                                                                                                                                                                                          |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `fespalier and its companions are pinned together, at one url and one release tag, and these are not:` then one line per package, then ``Pin them as fespalier is, then run `fsp upgrade --app` again`` | Each line is `{name} ({section}) comes from {how}, not from {url}` (a fork, or a folder) or ``{name} ({section}) is at `{ref}`, not a release tag like vX.Y.Z`` (a branch or a commit). Pin it as `fespalier` is by hand; a branch you test against stays a hand edit. |
| `fespalier comes from a checkout ({root}/fespalier) and {name} ({section}) from git: pin them one way, by hand`                                                                                         | A mix of a folder and git. Choose one.                                                                                                                                                                                                                                 |
| `fespalier comes from a checkout ({root}/fespalier): its version is the checkout's, and pubspec.yaml has no ref to move.` (exit 0)                                                                      | Not an error: a `path:` app (the examples, `fsp create --local-packages`). Update the checkout instead.                                                                                                                                                                |
| `fespalier and every companion in pubspec.yaml are at vX.Y.Z; nothing to move.` (exit 0)                                                                                                                | Up to date. With `dart run fespalier` the default release is the one you pin: pass `--version`.                                                                                                                                                                        |
| `note: dependency_overrides: {name} is {how}; left as it is` / `note: pubspec_overrides.yaml overrides {name}; left as it is`                                                                           | Not an error: an override to a folder (or another source) wins over the ref anyway. Remove it when you no longer develop against that folder.                                                                                                                          |
| `could not move the refs in pubspec.yaml safely ({why}); nothing was written. By hand: {change}`                                                                                                        | A `ref:` the line editor cannot replace in place (a value written over two lines). Make the change it names.                                                                                                                                                           |
| ``pubspec.lock still names the commits of the old refs: run `flutter pub get`.``                                                                                                                        | Not an error: `--no-pub-get`.                                                                                                                                                                                                                                          |
| ``pubspec.yaml now pins vX.Y.Z, and `flutter pub get` failed: {why}`` then ``Fix that and run `flutter pub get` (or put the old refs back).``                                                           | The tag does not exist (yet), no network, or a constraint of the new release that your other dependencies do not meet. `git diff pubspec.yaml` shows the moved refs.                                                                                                   |
| ``fsp {v} writes the code of v{v}: regenerate with the fsp of vX.Y.Z (`dart run fespalier gen`, or `fsp upgrade --version vX.Y.Z` first).``                                                             | Not an error: `--version` named another release than the running `fsp`'s, so `fsp gen` did not run. Regenerate with the matching `fsp`.                                                                                                                                |
| `fsp {v} was built before vX.Y.Z, so it does not carry the notes of the releases after v{v}: {link}`                                                                                                    | Not an error: the notes come from the `docs/migration.md` the binary was built with. Read the rest at the link.                                                                                                                                                        |
| `error: the following required arguments were not provided: --app` (clap, exit 2)                                                                                                                       | `--no-pub-get` is for `--app` only.                                                                                                                                                                                                                                    |
