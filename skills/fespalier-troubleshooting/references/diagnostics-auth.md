# Diagnostics: `fespalier_auth`

Since 0.9.0 (`packages/fespalier_auth/lib/src/`). These are not `fsp` diagnostics: `fsp` has none for auth, because
the packages add no file kind, no `fespalier:` key and no command. They are the **run-time messages** of the
packages, quoted from the code (each is asserted by a test) and followed by the cause and the fix.
[`fespalier-guards`](../../fespalier-guards/SKILL.md) explains the rules behind them.

## The session and the guards

| Message or symptom                                                                                                                                                                                                                        | Cause and fix                                                                                                                                                                                                                                                          |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Bad state: fespalier_auth: no AuthConfig. Return restoreAuth(config) from startup() in lib/app/startup.dart, or add authConfig.overrideWithValue(config) to your ProviderScope; in a test, pass overrides: fakeAuth(...) to pumpRouter.` | Something read `authSession`, `authHttpClient` or a guard helper before the app told `fespalier_auth` its `AuthConfig`. Return `restoreAuth(authSetup())` from `startup()`, or override `authConfig`; in a widget test pass `overrides: fakeAuth(...)` to `pumpRouter` |
| Signing in changes nothing: the user stays on the sign-in page                                                                                                                                                                            | The sign-in route has no guard of its own. Add `GuardResult guard(Ref ref, {String? from}) => redirectIfSignedIn(ref, from: from);` in `sign-in/guard.dart`, **beside** the guarded group, not inside it. The page needs no navigation code                            |
| The sign-in page shows `Nothing at /sign-in` (or your `not_found.dart`)                                                                                                                                                                   | `sign-in/` is inside the guarded group: its `from=` redirect loops. Move it beside `(signed-in)/` (the old "login page" trap, `guards-and-redirects.md`)                                                                                                               |
| A guarded page flashes, or the first frame is blank, on a cold deep link                                                                                                                                                                  | `startup()` does not return `restoreAuth(...)`, so the session restores at the first read and the guard answers a `Future` meanwhile. Return `restoreAuth(authSetup())` from `startup()` (synchronous with a synchronous store)                                        |
| `Bad state: fespalier_auth: not signed in`                                                                                                                                                                                                | `tokens()` was asked while nobody is signed in, or a request waited for a refresh and the user signed out meanwhile (`NotSignedIn`, a `StateError`). Guard the call, or let the guard that watches the session move the user                                           |
| `AuthRejected: the server refused the session (invalid_grant)` (with a description: `AuthRejected: the server refused the session (invalid_grant: Token is not active)`)                                                                  | The refresh token was refused. The session is over: the state is `SignedOut(reason: SignOutReason.expired)` and the sign-in page can say so. Not a bug in the app unless it happens at once after sign-in (a clock problem, or the session was refreshed twice: below) |
| `AuthRejected` right after a refresh succeeded, on a web app with two tabs, or an app that refreshes in a background isolate                                                                                                              | The server rotates refresh tokens (Keycloak's "Revoke Refresh Token") and a second place used the old one. The single flight is per `ProviderContainer`: refresh in one place, or turn rotation off (or give the realm a reuse count)                                  |
| `fespalier_auth: couldn't refresh the session: ClientException: Connection refused` (an `AuthUnavailable`, which is a `ClientException`)                                                                                                  | The refresh could not run: offline, a socket error or a 5xx. The session **stays**, and the next request tries again. Handle it like any `http.ClientException`; do not sign the user out                                                                              |
| `AuthCancelled: the sign-in was cancelled`                                                                                                                                                                                                | The user closed the browser sign-in. Not an error to report: a form should show nothing                                                                                                                                                                                |
| `The following FormatException was thrown while restoring the stored session:` (a `FlutterError.reportError`, library `fespalier_auth`)                                                                                                   | The stored session is not JSON, or is another version. It is reported once, deleted and the user is signed out. After an upgrade of the package it can be a session written by another release; signing in again fixes it                                              |
| `fespalier_auth: AuthConfig.apiOrigins is empty, so no request would carry the session; list your API's origins, e.g. apiOrigins: [Uri.parse('https://api.example.com')]`                                                                 | `authHttpClient` or `authorizer` was read with an empty `apiOrigins`. List the scheme, host and port of every API that should get the token; nothing else is sent one                                                                                                  |
| A request to your API goes with no `Authorization` header                                                                                                                                                                                 | Its origin is not in `AuthConfig.apiOrigins` (a different scheme, host or port counts), or nobody is signed in, or the request did not go through `authHttpClient`                                                                                                     |
| `ArgumentError`: `fespalier_auth: this session comes from the backend "firebase", but the configured backend is "fake"`                                                                                                                   | `adopt(session)` got a session another backend made. Adopt only what the configured backend built, or configure the right backend                                                                                                                                      |
| `Bad state: fespalier_auth: the access token is DPoP-bound (token_type DPoP), but the backend has no proof of possession: pass proof: DpopProof.device() (package:fespalier_sign_keypair) to the backend`                                 | The server returned a DPoP-bound token and the backend was built without a `proof`. Give the backend a proof of possession                                                                                                                                             |
| A sign-out button over a pushed page does nothing                                                                                                                                                                                         | A guard under a **pushed** page reacts only when you pop back to it. Navigate as well: `const HomeRoute().go(context)`                                                                                                                                                 |
| The previous user's data shows after signing in as another                                                                                                                                                                                | A `data.dart` that does not `ref.watch(authUserId)`, or a `dataCache` (since 0.8.1) that kept it. Watch the id, and clear the cache storage on sign-out                                                                                                                |

## OpenID Connect and Keycloak (`package:fespalier_auth/oidc.dart`)

`OidcException` (`OidcException: <message>`) is an answer `OidcBackend` cannot use. Each message below is asserted by a
test (`packages/fespalier_auth/test/oidc_test.dart`); the descriptions Keycloak itself sends were read from a live
Keycloak 26.8.0 (`fespalier-guards`, its `auth-backends.md` page). None of them carries a token, a code or a `state`.

| Message or symptom                                                                                                                                                                 | Cause and fix                                                                                                                                                                                                                                                                                                            |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `OidcException: the redirect's state does not match the sign-in that opened it`                                                                                                    | The redirect belongs to another sign-in: a second sign-in started while the first browser was open, or a stale tab came back. Disable the button while `signIn` is pending, and sign in again                                                                                                                            |
| `OidcException: the server answered the sign-in with error invalid_request: Missing parameter: code_challenge_method`                                                              | The Keycloak client does not require PKCE. Set the client attribute `pkce.code.challenge.method` to `S256` (Advanced settings, Proof Key for Code Exchange). `OidcBackend` always sends `S256`; `Invalid parameter: code challenge method is not matching the configured one` is the same setting, set to another method |
| `OidcException: the server answered the sign-in with error invalid_scope: Invalid scopes: openid nonsense`                                                                         | `scopes:` names a scope the realm does not have. Add the client scope in Keycloak, or take it out of `OidcBackend(scopes: ...)`                                                                                                                                                                                          |
| `OidcException: the server answered the sign-in with error login_required`                                                                                                         | `BrowserSignIn(prompt: 'none')` with no single-sign-on session. Retry without `prompt`, or with `prompt: 'login'`                                                                                                                                                                                                        |
| Keycloak's own page says `Invalid parameter: redirect_uri` (HTTP 400, **no redirect**: nothing comes back to the app)                                                              | `redirectUri` is not in the client's **Valid redirect URIs**. List it exactly and whole: `com.example.shop:/callback`, not `com.example.shop`. The page `Client not found.` is a wrong `clientId`                                                                                                                        |
| `OidcException: the token endpoint answered HTTP 400: invalid_grant: Incorrect redirect_uri`                                                                                       | The `redirect_uri` of the code exchange is not the one of the authorization request. `OidcBackend` sends the same one both times, so a proxy or a second configuration is rewriting one                                                                                                                                  |
| `OidcException: the token endpoint answered HTTP 400: invalid_grant: PKCE verification failed: Code mismatch` (or `Code not valid`)                                                | The code was used before (`Code not valid`; Keycloak then ends the session it made), or the verifier is not the challenge's because the redirect came from another sign-in. One sign-in at a time                                                                                                                        |
| `OidcException: the redirect comes from http://other.example, not http://localhost:8080/realms/shop`                                                                               | RFC 9207: the redirect's `iss` is not the configured issuer (a mix-up attack, or a second realm). Check `issuer`                                                                                                                                                                                                         |
| `OidcException: the redirect has no code`                                                                                                                                          | The redirect carried neither a `code` nor an `error`. Look at what the browser step returned (`flutter_web_auth_2` returns the whole URL)                                                                                                                                                                                |
| `OidcException: the ID token was issued by http://10.0.2.2:8080/realms/shop, not http://localhost:8080/realms/shop`                                                                | Keycloak's issuer is its configured hostname. On an Android emulator use `adb reverse tcp:8080 tcp:8080` and `localhost`, or start Keycloak with `--hostname=http://10.0.2.2:8080` and use that as `issuer`                                                                                                              |
| `OidcException: the ID token is for other-client, not for shop-app`                                                                                                                | The ID token's `aud` does not list `clientId`: it is not the Keycloak client the user signed in to                                                                                                                                                                                                                       |
| `OidcException: the ID token's nonce does not match the sign-in`                                                                                                                   | The token came from another authorization request. Sign in again                                                                                                                                                                                                                                                         |
| `OidcException: the ID token is not a JWT`, `the tokens carry no "sub" claim`, `the token endpoint's answer has no access_token`                                                   | The provider answered something other than OpenID Connect: a proxy's page, or `openid` is not in `scopes`. Look at the token endpoint's answer                                                                                                                                                                           |
| `OidcException: discovery at https://sso.example.com/realms/shop/.well-known/openid-configuration failed with HTTP 404` (or `did not answer JSON`, `did not answer a JSON object`) | `issuer` is wrong (Keycloak: `https://host/realms/<realm>`). Or spell the endpoints yourself: `OidcEndpoints.keycloak(issuer)` makes no request                                                                                                                                                                          |
| `OidcException: the discovery document's issuer ... is not ...`, `discovery at ... has no authorization_endpoint or token_endpoint`                                                | The document is another provider's, or a proxy rewrote it. Check `issuer`                                                                                                                                                                                                                                                |
| `AuthRejected: the server refused the session (invalid_grant: Session not active)` (or `Session doesn't have required client`, `Invalid refresh token`)                            | The session was ended on the server: a sign-out elsewhere, an admin, or a refresh token used twice (rotation: the whole session is then gone). The state is `SignedOut(reason: SignOutReason.expired)`; the user signs in again                                                                                          |
| `AuthRejected: the server refused the session (invalid_grant: there is no refresh token)`                                                                                          | The provider issued no refresh token (a client that does not allow one, or no `offline_access` where it is needed) and the access token expired. Ask for `offline_access`, or lengthen the access token                                                                                                                  |
| Signing out leaves the browser signed in, and the next sign-in goes straight through                                                                                               | The single-sign-on cookie. Use `preferEphemeral: true` in `FlutterWebAuth2Options`, `BrowserSignIn(prompt: 'login')`, or `endBrowserSession(session)`                                                                                                                                                                    |

### With DPoP, and the request layer

| Message or symptom                                                                                                             | Cause and fix                                                                                                                                                                                                                                                                                                                            |
| ------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `OidcException: the server does not accept ES256 DPoP proofs (dpop_signing_alg_values_supported: RS256, PS256)`                | The provider's discovery document does not list ES256 and the backend has a `proof`. The proofs `fespalier_auth` asks for are ES256                                                                                                                                                                                                      |
| `OidcException: the token endpoint answered HTTP 400: invalid_request: DPoP proof has already been used`                       | A proof was sent twice. A `RetryClient` **under** the session client (`authBaseClient` overridden with one) re-sends the same headers: the same signature and the same `jti`. Wrap the session client in the `RetryClient` instead, `RetryClient(ref.watch(authHttpClient))`, so each attempt asks the authorizer for its own proof      |
| `OidcException: the token endpoint answered HTTP 400: invalid_request: DPoP proof is not active`                               | The device's clock is off from the server's (Keycloak 26.8.0 refused a proof 20 seconds ahead and 120 seconds either way, and took one 20 seconds behind). Fix the clock. A server or a proxy that sends a `Date` header lets `DpopProof` correct itself once (`clockCorrectionThreshold`, 5 seconds); Keycloak sends none               |
| `OidcException: ...: invalid_request: DPoP proof is missing`                                                                   | The client requires DPoP-bound tokens ("Require DPoP bound tokens" in Keycloak) and the backend has no `proof:`. Give `OidcBackend(proof: ...)` a `ProofOfPossession`                                                                                                                                                                    |
| `OidcException: ...: invalid_request: DPoP Proof public key thumbprint does not match dpop_jkt`                                | The authorization request bound the code to one key and the code exchange was signed with another: the proof object was replaced, or its key regenerated, between the browser step and the exchange                                                                                                                                      |
| `AuthRejected: the server refused the session (invalid_grant: DPoP confirmation doesn't match DPoP proof)`                     | The refresh token is bound to a key this device no longer has (a restored backup, a wiped keychain). The user signs in again. `restoreAuth` already drops a session whose key is gone (`SignedOut(keyLost)`)                                                                                                                             |
| An API answers 401 with `WWW-Authenticate: DPoP algs="...", error="invalid_token"` to every request, though the token is fresh | The DPoP scheme was sent with no proof, or a proof with no `ath`, another `htu` or `htm`, another key, or a time that is off. Send the session through `authHttpClient` or `SessionInterceptor` only, so the scheme and the proof are the authorizer's. A `Bearer` header for a DPoP-bound token gets `Bearer ... error="invalid_token"` |
| A guard against re-sent writes (an idempotency check, a dio interceptor of your own) rejects a request after a refresh         | `SessionClient` and `SessionInterceptor` send a request again after a 401 and a refresh, or after a DPoP nonce. Let that send through: `isAuthReplay(request)` is true for it, and on dio `options.extra[authReplayKey]` (`'fespalier.auth.replay'`) is `true`                                                                           |
| A `DioException` whose `error` is an `AuthUnavailable`                                                                         | The refresh before or after a request could not run (offline, a 5xx). The session stays; `SessionInterceptor` reports it as the request's error. Show "offline" and do not sign the user out                                                                                                                                             |

## `fespalier_sign_keypair` (DPoP)

| Message or symptom                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Cause and fix                                                                                                                                                                                                                                                                                                                                                                             |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Unsupported operation: fespalier_sign_keypair: the web has no secure element for a DPoP key. Pass fallback: DpopFallback.software for a software key (on the web it does not survive a reload), or DpopFallback.bearer to send bearer tokens (the client must not require DPoP-bound tokens)` (a `DpopUnavailable`; `Windows`, `Linux` and `Fuchsia` say their own name)                                                                                               | `DpopProof.device()` on a platform with no secure element, with the default `DpopFallback.refuse`. Pick the fallback on purpose: `software` (a key in memory, lost on a web reload, so the session is signed out), or `bearer` (no DPoP: the Keycloak client must not require DPoP-bound tokens). `requireHardware: true` is `DpopUnavailable` there too, unless the fallback is `bearer` |
| `DpopProofInvalid: typ is JWT, not dpop+jwt` (or `alg is ..., not ES256`, `the jwk is not a public P-256 key`, `the signature does not verify`, `htm is GET, not POST`, `htu is ..., not ...`, `jti is missing`, `ath is missing`, `ath does not match the access token`, `ath is set on a request without an access token`, `nonce is ..., not ...`, `iat is 120 s from now`, `the key's thumbprint is ..., not ...`, `the proof is not a compact JWS of three parts`) | `verifyDpopProof` in a test or a demo server refused a proof, naming the first check that failed, in the order of that list. In a test it is usually the test: a `htu` with the wrong host, an `ath` for another token, a clock that is not the one `DpopProof` used (`withClock`), or `window:` too small                                                                                |
| `Bad state: fespalier_sign_keypair: the signer returned 70 bytes, not the 64-byte r\|\|s signature that ES256 needs`                                                                                                                                                                                                                                                                                                                                                    | A `DpopSigner` of your own returns an ASN.1 DER signature (about 70 bytes), which is what most platform APIs make. ES256 in a JWS is IEEE P1363: 32 bytes `r` then 32 bytes `s`                                                                                                                                                                                                           |
| `SecureSignerException(hardwareUnavailable): ...` on the first sign-in                                                                                                                                                                                                                                                                                                                                                                                                  | `requireHardware: true` on a device with no secure element: the iOS simulator has only the keychain, and an Android emulator may have a software keymaster. Leave `requireHardware` off for it, or test on a device                                                                                                                                                                       |
| `Bad state: fespalier_auth: the access token is DPoP-bound (token_type DPoP), but the backend has no proof of possession: pass proof: DpopProof.device() (package:fespalier_sign_keypair) to the backend`                                                                                                                                                                                                                                                               | The server returned a DPoP-bound token and the backend has no `proof`: `DpopFallback.bearer` returned null on this platform while the Keycloak client requires DPoP-bound tokens (or a test overrode the backend). Give the backend a proof, or switch off "Require DPoP bound tokens" for the client                                                                                     |
| The user is signed out at every web reload with DPoP (`SignedOut(reason: SignOutReason.keyLost)`)                                                                                                                                                                                                                                                                                                                                                                       | The key the stored session is bound to is gone: a software key lives in memory (`DpopFallback.software` without `softwareStore:`), and the session in the token store outlived it. On a device the same happens when the key is deleted while the session is kept. `restoreAuth` drops the session, and the user signs in again, which makes a new key                                    |
| `Because every version of fespalier_sign_keypair from path depends on fespalier from git ... and fespalier_sign_keypair from path is forbidden.` (also for `fespalier_auth`)                                                                                                                                                                                                                                                                                            | The three dependencies do not have the same `url` and `ref`. Use the same repository dependency, with the same tag, for `fespalier`, `fespalier_auth` and `fespalier_sign_keypair`. `The current Dart SDK version is ...` on pub get: flutter-sign-keypair needs Dart 3.12 and Flutter 3.44                                                                                               |

## Telemetry

`auth` spans (`#1 start auth restore backend=fake`, since 0.9.0) follow the installed sink: they need no
`telemetry: true`. A sink that switches **exhaustively** over `TelemetryOp` stops compiling on 0.9.0 until it has an
`auth` case (`The type 'TelemetryOp' isn't exhaustively matched by the switch cases since it doesn't match the pattern 'TelemetryOp.auth'`):
add the case, or end the switch with `_ =>`. No span carries a token, an id, a claim, an e-mail or a URL
([`fespalier-observability`](../../fespalier-observability/SKILL.md), its conventions page).
