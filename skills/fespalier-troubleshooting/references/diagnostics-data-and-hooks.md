# Diagnostics: `data.dart`, `action.dart`, guards, redirects and transitions

As of v0.4.0 (`cli/src/resolve.rs`). Messages are the text `fsp` prints; the cause
and the fix follow each.

| `` `freshness` applies to the provider fespalier makes of a data() function, and this data.dart exports its own `data` provider; call `freshData(ref, const Freshness(...), value)` inside it instead ``                         | `freshness` beside `final data = FutureProvider<T>(...)`                                                                                        |

| `` `dataCache` applies to the provider fespalier makes of a data() function, and this data.dart selects a provider of your own; persist that provider with Riverpod's `persist` (from package:fespalier/persist.dart) instead `` | `dataCache` beside a selector                                                                                                                   |
| `` `dataCache` applies to the provider fespalier makes of a data() function, and this data.dart exports its own `data` provider; persist it with Riverpod's `persist` (from package:fespalier/persist.dart) instead ``           | `dataCache` beside a provider form                                                                                                              |

An app with a public top-level `freshness` or `dataCache` of another type gets the first error of its kind since
0.8.1: rename it (a private `_freshness` is never read).

Runtime, since 0.8.1, `debugPrint` in debug only (never an error of the route): `fespalier: dataCache of <name> could not read a saved value, dropped it: <error>`
(a saved value that did not decode, or a storage whose `read` threw; the entry is deleted and the load goes on) and
`fespalier: dataCache of <name> could not save: <error>` (the storage's `write` or `delete` failed, or `encode`
threw; nothing is saved and the page is unaffected).

Runtime, not `fsp`: a selector that returns `provider.select(...)` builds and watches fine, but
`refresh` and `retry` throw a `StateError` (`data.dart selected ..., which is not a
FutureProvider, StreamProvider or generated async provider, so it cannot be invalidated
or refreshed. Return the provider itself from data() ...`).

points at the function or the parameter. The segment and query parameter messages are
`data.dart`'s, with that name.

### Companions: `form()`, `validate()` and `optimistic()` (since 0.8.1)

`<f>`, `<v>` and `<o>` are the companion's own name (`form`, `approveValidate`, ...), `<name>` the
action's (`action`, `approve`), `<input>` the text of its `input` type, `<hook>` the form hook
(`useForm`, `useApproveForm`). The code frame points at the companion. All are errors except the
last, a warning. Since 0.11.0 a `form()` also needs the `fespalier_forms` package (the first row). A
companion that is wrong is left out and its action still works; the companions
of an action that failed to resolve are not checked.

## `leave.dart`

Since 0.11.0 (`cli/src/resolve.rs`, `packages/fespalier/lib/src/leave.dart`). The rules behind them are in
[`fespalier-routing`](../../fespalier-routing/references/leaving-a-page.md). The errors are at the function or at the parameter at fault.

| Message                                                                                                                                                                                | Cause and fix                                                                                                                                                                                                                                           |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ``expected `LeaveResult leave(BuildContext context, Ref ref, {...})`: true lets the page go, false keeps it``                                                                          | The file has no function called `leave` (a helper alone does not count).                                                                                                                                                                                |
| ``leave() must return `LeaveResult` (`FutureOr<bool>`): true lets the page go, false keeps it``                                                                                        | The return type is missing or another one (`void`, `Future<void>`). Use `LeaveResult`, `FutureOr<bool>`, `Future<bool>` or `bool`.                                                                                                                      |
| `leave.dart is asked before this folder's page goes, and this folder has no page.dart (a layout's shell has no onExit in go_router: put a leave.dart beside each page that needs one)` | A `leave.dart` in a folder with no `page.dart` (a layout's shell has no `onExit` in go_router). Move it beside each page that needs one. The one page-less folder that may have one is a flow section (`action.dart` with `const steps`, since 0.11.0). |
| `a redirect.dart route never stays on screen, so there is nothing to leave: remove leave.dart`                                                                                         | A `leave.dart` beside a `redirect.dart`. Remove it.                                                                                                                                                                                                     |
| `` leave() runs outside the page's widget tree (go_router hands it the root navigator's context): take `Ref` ``                                                                        | A positional `WidgetRef`. Take `Ref ref`; the `BuildContext` it gets is the root navigator's.                                                                                                                                                           |
| ``leave() takes `Ref ref`; `ProviderContainer` is the older form of guards, not of leave()``                                                                                           | A positional `ProviderContainer`. Take `Ref ref`.                                                                                                                                                                                                       |
| ``leave()'s positional parameters are `BuildContext context` then `Ref ref`, each optional; the rest are named``                                                                       | A positional parameter in another order or type, or `PageLeave` written positionally. Everything but `context` and `ref` is named: `{required PageLeave page}`.                                                                                         |
| `` the page that is going is `PageLeave page`; name the parameter `page` ``                                                                                                            | A `PageLeave` parameter under another name. It is bound by type and name.                                                                                                                                                                               |

At run time (a `FlutterError.reportError` report, library `fespalier`):

| Message                                               | Cause and fix                                                                                                                       |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `while running leave() of orders/$id/edit/leave.dart` | `leave()` threw (now or in its `Future`). The page was let go: a broken `leave()` never traps the user. Fix the exception it names. |

Symptoms with no message:

- **`leave()` never runs on a tab switch.** By design: the page is parked, not gone. Use drafts for what a parked tab holds.
- **A page leaves without asking when the whole `ShellRoute` is popped (Flutter below 3.38).** go_router 17.0 to 17.3 skips the leaf's `onExit`; fixed in 17.4.0.
- **The iOS swipe does nothing on a page with a `leave.dart`.** It is off while the page has no registered source or a dirty one; with all sources clean it pops and asks.
- **A sign-out redirect asks.** A guard's redirect is asked like any navigation: check auth in `leave()`, or `leaveWithoutAsking(router, signOut)`.
- **A `leave()` in the parent folder is asked too.** go_router asks every exiting match, deepest first; it is not inherited, both run.

## Multi-page forms: `const steps`

Since 0.11.0 (`cli/src/resolve.rs`, `cli/src/forms.rs`; the rules are in [`fespalier-data`](../../fespalier-data/references/flows.md)).
Each error is at the `steps` variable, at a step's name or at the field it names, unless it says otherwise; a flow that has
one stays a plain form.

| Message                                                                                                                                                                                                          | Cause and fix                                                                                                                                                                     |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `` `steps` must be a `const` map literal from a step folder's name to the list of the input's fields it asks for, in order ``                                                                                    | `steps` is a list, a `final`, an empty map, has a repeated key or a value that is not a list of string literals. Write `const steps = {'name': ['name'], 'review': <String>[]};`. |
| `` `steps` makes `action()` a form over several pages, so action.dart must be a section's: a folder with a layout.dart and no page.dart ``                                                                       | The `action.dart` is beside a `page.dart`, or has no `layout.dart`. A flow is a section: move the action to the folder that holds the layout and the step folders.                |
| `` `'<name>'` is a step, but `<folder>/<name>/page.dart` does not exist: each step is a child folder with a page.dart ``                                                                                         | The key names no direct child folder with a `page.dart` (a typo, a `(group)` or dynamic folder, a nested path like `'a/b'`). Create `<folder>/<name>/page.dart` or fix the key.   |
| `` `'<field>'` is not a field of `<Input>` ``                                                                                                                                                                    | A step lists a name that is not a field of the input record. Fields are the names in the typedef or record type of `input`.                                                       |
| `` `'<field>'` is asked for by `'<a>'` and `'<b>'`: a field belongs to one step ``                                                                                                                               | Two steps (or one twice) list the same field. Keep it in the step that asks for it.                                                                                               |
| `` `'<field>'` belongs to no step: add it to the step that asks for it ``                                                                                                                                        | A field of the input is in no step. Add it to one (a field a step never shows still needs an owner).                                                                              |
| `` `steps` without `form()`: a flow starts from `form()` ``                                                                                                                                                      | There is no `form()` beside the action. Add `Input form() => (...)`.                                                                                                              |
| ``expected `bool skip(<Section>Step step, <Input> input)` (`<name>Skip` for an action called `<name>`)``                                                                                                         | The `skip` function has another signature. The step type is the generated enum (`SignupStep`), and it returns `bool`.                                                             |
| `` `draft` can't be a key of an action with a form: its hook, `useFlow`, takes a parameter called `draft`; rename it `` (also `messages`, `validation`)                                                          | The reserved-key error, for a flow's hook. Rename the segment or query parameter.                                                                                                 |
| `` `<form>()` can't take a value in a flow: `resume` runs in a guard, before any data is loaded, and builds the form from `<form>()` alone ``                                                                    | A flow's `form()` takes no parameter. Start from constants; the draft and the user fill the rest.                                                                                 |
| `a flow sits at a path with no dynamic segment for now: its steps are `go`ne to by their typed routes, and `<keys>` would have to be given to each; move the section out of the folder that takes it`            | The flow's folder is under a `$param` folder. Move it to a static path (a flow of an order can be `checkout/`, with the id in the draft's key or the data).                       |
| `a flow's path can't be localized for now (a `paths`in a route.dart at or above it):`within` is its path as the folders spell it`                                                                                | A `route.dart` `paths` at or above the flow. Keep the flow's path unlocalized.                                                                                                    |
| `a flow can't sit inside another flow: this section is below the flow of <folder>/action.dart; flows are one level, and a step is a page that holds no flow of its own`                                          | A section with `steps` below another one's. Flows are one level: make the inner one a sibling.                                                                                    |
| `a step of a flow is asked by the section's leave.dart: remove this one (a navigation inside <folder> is never asked, and leaving it is asked once, by the section's leave.dart)` (at the step's own leave.dart) | A `leave.dart` in a step's folder. The section's leave.dart is the step's; delete the step's (a flow section with no leave asks nothing).                                         |
| ``a flow's leave() is asked on every step of the section, so it reads no segment, query parameter or `extra`: `Uri uri` has the location`` (the leave.dart of a flow)                                            | The flow's `leave()` takes a parameter bound to the URL. Take `Uri uri` and read it yourself.                                                                                     |

A flow's `leave.dart` is **not** the `leave.dart is asked before this folder's page goes, and this folder has no page.dart` error:
that one is for a page-less folder that is no flow (`action.dart` with `const steps` beside the `layout.dart`).

## `transition.dart` and `present.dart`

| Message                                                                                         | Cause and fix                                                                                           |
| ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `` expected `Page<void> transition(LocalKey key, Widget child)` `` (or `present`)               | No function of that name                                                                                |
| `` transition() must return a Page, e.g. `Page<void>` ``                                        | Return a `Page`                                                                                         |
| `` transition() must take the page as `Widget child` ``                                         | No `child` parameter                                                                                    |
| `` can't fill `other`: transition() gets `key`, `child` and `state` ``                          | Only `key`, `child`, `state` (and `shell`/`isShell`, a `bool`)                                          |
| `` `key` gets the page's key, a ValueKey<String>, but it's declared ... ``                      | `key` may be `LocalKey`, `Key`, `ValueKey`, `ValueKey<String>`, `ValueKey<Object>`, `ValueKey<dynamic>` |
| warning `present.dart builds this folder's page, but there is no page.dart here; it is ignored` | `present.dart` needs a `page.dart` beside it                                                            |

## Runtime errors that are not from `fsp`

- **A dialog or sheet opens over a blank screen on a deep link**: the route has no parent
  page above it; put its folder below a page (`fespalier-layouts`).
- **`No Material widget found` / `MaterialLocalizations` missing** for a dialog or sheet: a
  `MaterialApp` (or a `Localizations` with the Material delegate) must be above the router.
- **A `BadSegment` exception** is thrown inside generated code and turned into
  `not_found.dart`; you should never see it unless you call `Segment.asInt` yourself.
