# Diagnostics: `data.dart`, `action.dart`, guards, redirects and transitions

As of v0.4.0 (`cli/src/resolve.rs`). Messages are the text `fsp` prints; the cause
and the fix follow each.

## `data.dart`

| Message                                                                                                                                                                                                                      | Cause and fix                                                                                                                                                                |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ``data() must take `Ref ref` first``                                                                                                                                                                                         | The function form's first parameter is a positional `Ref ref`                                                                                                                |
| `data() needs an explicit return type (Future<T>, Stream<T> or T)`                                                                                                                                                           | `data(Ref ref) async => 1` has no type; write `Future<int> data(...)`                                                                                                        |

| `` `id` isn't a segment of this path (it has none); for a query parameter make it optional and nullable, e.g. `String? id` ``                                                                                                | A named parameter that is neither a segment of this path nor an optional nullable query parameter                                                                            |

Use a nullable `String`, `int`, `double` or `bool`, an enum, or a `List` of those                             |
| `` `data` must be a FutureProvider, StreamProvider, AsyncNotifierProvider or StreamNotifierProvider `` (`..., not Provider`)                                                                                                 | `final data = ...` of another kind (or not a call)                                                                                                                           |

`freshness` and `dataCache` (since 0.8.1) are variables of a `data.dart` that `fsp` reads by name; the error is at the
variable, with a code frame. They apply to the function form that returns a `Future<T>`, a `FutureOr<T>` or a `T`:

| Message                                                                                                                                                                                                                          | Cause and fix                                                                                                                                   |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `` `freshness` must be a `Freshness(...)`: write `const freshness = Freshness(staleTime: Duration(minutes: 5));` ``                                                                                                              | The initializer is not a `Freshness(...)` call (`const freshness = Duration(minutes: 5);`, a function call, a variable). Also in a `route.dart` |
| `` `freshness` is declared twice ``                                                                                                                                                                                              | Two `freshness` in one file; the error is at the second. Also in a `route.dart`                                                                 |
| `` `freshness` is for a data() that loads once, and this one returns a `Stream`, which is live: nothing in it goes stale. Drop `freshness`, or return a `Future` ``                                                              | `freshness` beside `Stream<T> data(...)`                                                                                                        |
| `` `freshness` applies to the provider fespalier makes of a data() function, and this data.dart selects a provider of your own; call `freshData(ref, const Freshness(...), value)` inside that provider instead ``               | `freshness` beside a `ProviderListenable<AsyncValue<T>> data(...)`. Give the rules to your own provider with `freshData`                        |
| `` `freshness` applies to the provider fespalier makes of a data() function, and this data.dart exports its own `data` provider; call `freshData(ref, const Freshness(...), value)` inside it instead ``                         | `freshness` beside `final data = FutureProvider<T>(...)`                                                                                        |
| `` `dataCache` must be a `DataCache(...)` or `DataCache.json(...)`: write `final dataCache = DataCache<Product>.json(toJson: ..., fromJson: ...);` ``                                                                            | The initializer is not a `DataCache`, `DataCache<T>`, `DataCache.json` or `DataCache<T>.json` call                                              |
| `` `dataCache` is declared twice ``                                                                                                                                                                                              | Two `dataCache` in one file; the error is at the second                                                                                         |
| `` `dataCache` saves the last value of a data() that loads once, and this one returns a `Stream`; drop `dataCache`, or return a `Future` ``                                                                                      | `dataCache` beside `Stream<T> data(...)`                                                                                                        |
| `` `dataCache` applies to the provider fespalier makes of a data() function, and this data.dart selects a provider of your own; persist that provider with Riverpod's `persist` (from package:fespalier/persist.dart) instead `` | `dataCache` beside a selector                                                                                                                   |
| `` `dataCache` applies to the provider fespalier makes of a data() function, and this data.dart exports its own `data` provider; persist it with Riverpod's `persist` (from package:fespalier/persist.dart) instead ``           | `dataCache` beside a provider form                                                                                                              |

An app with a public top-level `freshness` or `dataCache` of another type gets the first error of its kind since
0.8.1: rename it (a private `_freshness` is never read).

Runtime, since 0.8.1, `debugPrint` in debug only (never an error of the route): `fespalier: dataCache of <name> could not read a saved value, dropped it: <error>`
(a saved value that did not decode, or a storage whose `read` threw; the entry is deleted and the load goes on) and
`fespalier: dataCache of <name> could not save: <error>` (the storage's `write` or `delete` failed, or `encode`
threw; nothing is saved and the page is unaffected).

Runtime, not `fsp`: a selector that returns `provider.select(...)` builds and watches fine, but
`refresh` and `retry` throw a `StateError` (`data.dart selected ..., which is not a
FutureProvider, StreamProvider or generated async provider, so it cannot be invalidated
or refreshed. Return the provider itself from data() ...`).

## `action.dart`

Since 0.5.0. `<name>()` is the function's own name (`action()`, `approve()`); the code frame
points at the function or the parameter. The segment and query parameter messages are
`data.dart`'s, with that name.

| Message                                                                                                                                                                                                     | Cause and fix                                                                                                                  |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `action.dart has nothing to write to: put it beside a page.dart (the route it belongs to) or, in a folder without a page, beside the layout.dart of a section`                                              | The folder has neither a `page.dart` nor a `layout.dart` (a `redirect.dart` doesn't count): move the file                      |
| ``expected `Future<T> action(Ref ref, {...segments, required Input input})`; any public function that takes a `Ref` first is an action``                                                                    | No public function takes `Ref ref` first (and none is called `action`)                                                         |
| ``<name>() must take `Ref ref` first``                                                                                                                                                                      | A function called `action` whose first parameter isn't a positional `Ref`                                                      |
| ``<name>() needs an `input` parameter, the value it writes: `{required Input input}`; segments and query parameters are its other named parameters``                                                        | No parameter called `input`                                                                                                    |
| ``<name>() takes `input` as a named parameter, e.g. `{required Input input}` ``                                                                                                                             | `input` is positional                                                                                                          |
| `` `input` of <name>() must be `required`: there is nothing to run without it ``                                                                                                                            | `Object? input` with no `required`                                                                                             |
| ``give `input` a type: it is what the action is called with``                                                                                                                                               | `required input`, no type: the generated `submit` has to name it                                                               |
| ``<name>() takes segments as named parameters, e.g. `{required int id}` ``                                                                                                                                  | A positional parameter after `ref`                                                                                             |
| `` `amount`isn't a segment of this path ($id); for a query parameter make it optional and nullable, e.g.`String? amount` ``                                                                                 | A named parameter that is neither a segment, an optional nullable query parameter nor `input`                                  |
| `<name>() needs an explicit return type (Future<T>, FutureOr<T> or T)`                                                                                                                                      | `action(Ref ref, ...) async => ...` with no type                                                                               |
| `<name>() returns a Stream, but an action is one write with one result: return a Future<T>, FutureOr<T> or T`                                                                                               | A `Stream` return                                                                                                              |
| ``give the Future of <name>() its type argument, e.g. `Future<Refund>` ``                                                                                                                                   | A bare `Future` (or `FutureOr`)                                                                                                |
| `` `invalidates` must be a const list literal of typed routes and sections: `const invalidates = [OrderRoute, TeamsTeamIdSection];`, or `const invalidates = <Object>[];` for none ``                       | `final invalidates`, a non-list, or an element that isn't a plain name (`OrderRoute.data`, a string, a spread)                 |
| `` `invalidates`names`X`, which is neither a typed route nor a section handle; list classes like `OrderRoute`or`TeamsTeamIdSection` ``                                                                      | A name that is no route class (`XRoute`) or section handle (`XSection`) of this app                                            |
| `` `invalidates` names `X`, which has no data.dart: there is nothing to invalidate ``                                                                                                                       | A route or section without a `data.dart`                                                                                       |
| ``<data file> is keyed by `q`, which <name>() doesn't take, so it can't tell which one to invalidate after a success: take it (`String? q`), or list what to invalidate with `const invalidates = [...]` `` | The default set includes data keyed by something the action doesn't take. Take the parameter, or list other routes             |
| ``<data file> is keyed by `shop`, which <name>() doesn't take, so it can't tell which one to invalidate after a success: take it (`String shop`), or leave that route out of `invalidates` ``               | The same, for a route named in `invalidates`                                                                                   |
| ``<name>() takes `id` as int, but <data file> is keyed by it as String``                                                                                                                                    | The action's key type isn't the data's                                                                                         |
| ``the helper of <name>() would be called `go`, which is already a member of the typed route; rename the function`` (also `the provider of`, `the hook of`)                                                  | A function named like a member of the route class (`go`, `refresh`, `watch`, `data`, ...). `action` and its own names are fine |
| ``the helper of <name>() would be called `x`, which is already `x`, a segment or query parameter of the route; rename the function``                                                                        | A function named like a segment or query parameter (a field of the route class)                                                |
| ``the helper of submit() would be called `submit`, which is already the helper of action(); rename the function``                                                                                           | Two actions whose helpers meet (`action` has `submit`, `useAction`, `action`; `x` has `x`, `useX`, `xAction`)                  |
| `` `watch` can't be a key of a section's action: the section's typed handle has a member called `watch`; rename it ``                                                                                       | A section action's key named like a member of the section handle                                                               |
| ``the section's typed handle `TeamsTeamIdSection` is already taken by <file>; (group) folders don't add to the name, so rename a folder``                                                                   | Two folders name the same handle (also for an action-only section)                                                             |

Runtime, not `fsp`: an action does not throw out of a page that is gone, and never
retries; a `StateError` ("An action tried to invalidate ...") would be a bug in the
generated list.

### Companions: `form()`, `validate()` and `optimistic()` (since 0.8.1)

`<f>`, `<v>` and `<o>` are the companion's own name (`form`, `approveValidate`, ...), `<name>` the
action's (`action`, `approve`), `<input>` the text of its `input` type, `<hook>` the form hook
(`useForm`, `useApproveForm`). The code frame points at the companion. All are errors except the
last, a warning. Since 0.11.0 a `form()` also needs the `fespalier_forms` package (the first row). A
companion that is wrong is left out and its action still works; the companions
of an action that failed to resolve are not checked.

| Message                                                                                                                                                                                                                                                                                                                            | Cause and fix                                                                                                                                                                                                                                                                 |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `` `<form>()` is the form of `<action>()`, and since 0.11.0 forms are in the fespalier_forms package: add `fespalier_forms` under `dependencies:` in pubspec.yaml, with the same git `url` and `ref` as fespalier `` (since 0.11.0; error at each `form()`)                                                                        | `fespalier_forms` is not under `dependencies:`: add it next to `fespalier` at the same `url` and `ref`, `flutter pub get`, restart `fsp watch` or `fsp dev` if one is running, `fsp gen` (`fespalier-data`, `references/forms.md`). Reads `pubspec.yaml` alone, not `pub get` |
| ``<f>() is the form of <name>(): it gives the form its first values from the data the page passes, so it takes that value (or nothing), not a `Ref` ``                                                                                                                                                                             | `form(Ref ref, ...)`. This is also what an old _action_ called `form` beside `action` now is: rename it                                                                                                                                                                       |
| `<f>() needs an explicit return type: the input of <name>(), <input>`                                                                                                                                                                                                                                                              | `form(Profile p) => ...` with no type: return the input's type                                                                                                                                                                                                                |
| ``<f>() returns `X`, but <name>() takes `<input>` as `input`: the form builds the action's input, so they are the same type``                                                                                                                                                                                                      | The return type text differs from the `input` type text (a typedef and the record it names are different texts)                                                                                                                                                               |
| ``the form of <name>() needs the fields of its input, and `<input>` is not a record type declared here: take `input` as a record with named fields (`required ({int amount, String note}) input`), or as a typedef of one declared in action.dart``                                                                                | The input is a class, a `String`, or a typedef declared in another file                                                                                                                                                                                                       |
| ``the form of <name>() needs a name for each field of its input, and `<input>` has positional fields: name them, e.g. `({int amount, String note})` ``                                                                                                                                                                             | `(int, String)`: give the fields names                                                                                                                                                                                                                                        |
| ``<f>() takes at most one parameter, positional and required: the value the form starts from, which the page passes to `<hook>` as `data:` ``                                                                                                                                                                                      | Two parameters, a named one or an optional one                                                                                                                                                                                                                                |

outside a `HookWidget` is `flutter_hooks`' own assertion.

## Runtime errors that are not from `fsp`

- **A dialog or sheet opens over a blank screen on a deep link**: the route has no parent
  page above it; put its folder below a page (`fespalier-layouts`).
- **`No Material widget found` / `MaterialLocalizations` missing** for a dialog or sheet: a
  `MaterialApp` (or a `Localizations` with the Material delegate) must be above the router.
- **A `BadSegment` exception** is thrown inside generated code and turned into
  `not_found.dart`; you should never see it unless you call `Segment.asInt` yourself.
