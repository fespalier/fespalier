# Diagnostics: `fsp dev`, `fsp build`, `fsp run` and `tasks:` (since 0.9.0)

As of 0.9.0 (`cli/src/tasks.rs` for the config and the commands, `cli/src/dev.rs`, `cli/src/dev_state.rs`, `cli/src/dev_tui.rs`,
`cli/src/procs.rs` and `cli/src/daemon.rs` for `fsp dev`). Messages are quoted as they are printed, to stderr unless noted. The user
documentation is the docs section
[Running your app: `fsp dev`](https://github.com/fespalier/fespalier/blob/main/docs/cli.md#running-your-app-fsp-dev); the schema and the keys are in
`fespalier`, `references/cli-and-config.md`.

`tasks:` is read, and checked, only by `fsp dev`, `fsp build` and `fsp run`: `fsp gen`, `check` and `watch` never report a mistake in
it. An `fsp` older than 0.9.0 rejects the key itself, with ``invalid pubspec.yaml: fespalier: unknown field `tasks`, expected one of ...``
(see `diagnostics-config-and-meta.md`): `dart run fespalier` runs the `fsp` that matches the package, so a team stays in step.

## A mistake in `tasks:`

Printed without a code frame, exit 1. `{name}` is the task, `{v}` the value as the pubspec spells it (a string as it is, anything else
as JSON), `{i}` counts from 1.

| Message                                                                                                                                                           | Cause and fix                                                                                                                                                                                                             |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `` `fespalier.tasks` must be a map of task names to tasks, e.g. `codegen: dart run build_runner build -d` ``                                                      | `tasks:` holds a list or a string. Make it a map from task name to task.                                                                                                                                                  |
| `` `fespalier.tasks`: `{name}` is not a task name; use lower-case letters, digits, `_` and `-`, starting with a letter ``                                         | `Dev`, `1x`, `a b`. Task names are `[a-z][a-z0-9_-]*`.                                                                                                                                                                    |
| `` `fespalier.tasks.{name}` must be a command (a string, or a list of words) or a map with `run`, `before`, `with`, `after`, `env` and `hot_reload`, got `{v}` `` | A task that is a number, a bool or empty (`codegen:` with nothing after it).                                                                                                                                              |
| `` `fespalier.tasks.{name}` has an unknown key `{key}`; a task takes `run`, `before`, `with`, `after`, `env` and `hot_reload` ``                                  | A misspelled key (`watch:` for `with:`).                                                                                                                                                                                  |
| `` `fespalier.tasks.{name}.run` must be a command: a string the shell runs, or a list of words run without a shell (`[flutter, run]`), got `{v}` ``               | `run` is a number, `""`, `[]`, or a list with something that is not a string (`[flutter, 1]`: quote the number). A task that is only `codegen: ""` says this too.                                                         |
| `` `fespalier.tasks.{name}.before` must be a command or a list of commands, got `{v}` `` (also `after`)                                                           | `before` or `after` is a number or a map. Write a command, or a list of them.                                                                                                                                             |
| `` `fespalier.tasks.{name}.before[{i}]` must be a command: a string the shell runs, or a list of words run without a shell, got `{v}` `` (also `after`)           | One item of the list is not a command. **A list of strings is a list of shell commands**: `before: [dart, run, x]` is three of them (`dart`, `run`, `x`). For one command with no shell write `before: [[dart, run, x]]`. |
| `` `fespalier.tasks.{name}.with` must be a map of names to commands, e.g. `build_runner: dart run build_runner watch -d`, got `{v}` ``                            | `with` is a string or a list. It is a map from a pane's name to its command.                                                                                                                                              |
| `` `fespalier.tasks.{name}.with`: `{n}` is not a name; use letters, digits, `_` and `-`, at most 20 ``                                                            | A pane name with a space or a dot, or longer than 20 characters.                                                                                                                                                          |
| `` `fespalier.tasks.{name}.with`: `{n}` is the name of a pane of fsp dev's own; pick another ``                                                                   | `flutter` and `fsp` are panes of `fsp dev` itself.                                                                                                                                                                        |
| `` `fespalier.tasks.{name}.with.{n}` must be a command: a string the shell runs, or a list of words run without a shell, got `{v}` ``                             | The command of a `with` entry is not a non-empty string or list of strings.                                                                                                                                               |
| `` `fespalier.tasks.{name}.env` must be a map of variable names to values, got `{v}` ``                                                                           | `env` is a list or a string.                                                                                                                                                                                              |
| `` `fespalier.tasks.{name}.env`: `{k}` is not a variable name (letters, digits and `_`, not starting with a digit) ``                                             | `1BAD`, `A-B`.                                                                                                                                                                                                            |
| `` `fespalier.tasks.{name}.env.{k}` must be a string, a number or a boolean, got `{v}` ``                                                                         | A list or a map as a value. Numbers and bools are written as YAML spells them (`8080`, `true`).                                                                                                                           |
| `` `fespalier.tasks.{name}.hot_reload` must be `true` or `false`, got `{v}` ``                                                                                    | `hot_reload: maybe`.                                                                                                                                                                                                      |
| `` `fespalier.tasks.{name}.hot_reload` is only read by `fsp dev`; move it under `tasks: dev:` ``                                                                  | `hot_reload` on `build` or on a task of your own.                                                                                                                                                                         |
| `` `fespalier.tasks.{name}` has no `run`; only `dev` and `build` have a default command ``                                                                        | A task of your own with only `before` or `after`. Add `run`.                                                                                                                                                              |

## `fsp dev` does not start, or stops

| Message                                                                                                                                                                                            | Cause and fix                                                                                                                                                                                                                                      |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ``fsp dev needs lib/app.g.dart: fix the errors above, then run `fsp dev` again``                                                                                                                   | The first generation failed and there is no output yet. Fix the errors printed above, exit 1.                                                                                                                                                      |
| `warning: lib/app.g.dart is out of date until the errors above are fixed; fsp dev keeps watching`                                                                                                  | The first generation failed but an earlier output exists. `fsp dev` goes on with it and regenerates when you fix the errors.                                                                                                                       |
| ``no device to run on: `flutter devices` lists none that this project supports. Start an emulator or a simulator, connect a phone, or enable a platform with `flutter create --platforms=web .` `` | `flutter devices --machine` lists no supported device. Exit 1.                                                                                                                                                                                     |
| ``more than one device: pick one with `fsp dev -- -d <id>` (ids: macos, chrome)``                                                                                                                  | Several devices and no terminal to ask in (CI, an IDE's run panel, `fsp dev --no-tui` with stdin piped). Pass one after `--`. Exit 1. On a terminal `fsp dev` asks instead (a picker, or `pick a device [1-2]:` in plain mode).                    |
| ``warning: could not list the devices (`flutter devices --machine`: exit 1); flutter run picks one``                                                                                               | `flutter devices --machine` failed (or `: it printed no JSON`, or `` `flutter` is not on PATH ``). `fsp dev` goes on with no `-d`; flutter then picks, or prints its own list and exits.                                                           |
| `` `{line}` is not one of the devices: run `fsp dev` again, or pick one with `fsp dev -- -d <id>` ``                                                                                               | An answer to `pick a device [1-2]:` that is not a number in the list. Exit 1.                                                                                                                                                                      |
| `flutter run exited (exit {code})`                                                                                                                                                                 | Flutter ended by itself (a Gradle error, a crash, the app closed on the device). In the full-screen view the header says `✗ stopped (exit N)` and stays open: fix it and press `R`. In plain mode `fsp dev` ends with that code and skips `after`. |
| `[{name}] exited (exit {code}); fsp dev keeps running`                                                                                                                                             | A `with` command ended. `fsp dev` keeps running and its tab is marked `✗` (`■` for exit 0). A watcher that exits at once usually wants a flag (`-d`) or a different working folder.                                                                |
| `stopping flutter… (press q or Ctrl-C again to kill it)`                                                                                                                                           | `q` or Ctrl-C: `app.stop` goes to flutter, then the `with` groups get SIGTERM (SIGKILL after 5 s). The second press kills every group at once and exits 130.                                                                                       |
| ``the `run` command has not connected over flutter's --machine protocol yet; hot reload needs `flutter run` ``                                                                                     | `r` or `R` before flutter said `daemon.connected`: flutter is still starting, or `run:` is a command that is not `flutter run` and does not pass `--machine` on. Put `"$@"` after the flutter call in a script.                                    |
| `hot reload is off: flutter run started without it (--no-hot, --profile or --release)`                                                                                                             | `r` or `R` against an app flutter runs without hot reload. Nothing reloads by itself either.                                                                                                                                                       |
| `no DevTools URL yet` / `no web URL: the app runs on Pixel 8` / `could not open {url}: {why}`                                                                                                      | `d` before the VM service is up; `o` when the app is not on the web; or `open`, `xdg-open` or `start` failed. In plain mode `d` and `o` print the URL instead of opening it.                                                                       |
| `warning: could not take over the terminal ({why}); plain output`                                                                                                                                  | Raw mode or the alternate screen could not be entered. `fsp dev` goes on in plain mode.                                                                                                                                                            |

Exit codes of `fsp dev`: 0 after `q`; 130 after a signal (SIGTERM, SIGHUP, Ctrl-C in plain mode) or a second `q`; flutter's own code when it
ended by itself with a failure; a failed `before` step's code. `after` runs when flutter did not fail by itself.

## Symptoms

- **Flutter lists several devices and exits** (`Multiple devices found`...). `run:` is custom (`fvm flutter run`, a script), so `fsp dev` did not
  ask `flutter devices` which to use: it cannot know which flutter to ask. Put `-d <id>` in `run`, or after `--`.
- **A `with` command's output appears late, or in bursts.** The tool buffers its output when it is piped (it is, to its pane). Ask it
  to flush: `python -u`, `PYTHONUNBUFFERED=1` in `env`, `--line-buffered`, `stdbuf -oL`.
- **The app looks stale after a hot reload.** A reload keeps the router, and the router is built once: a new, removed or renamed route, a
  changed pattern or a new `data.dart` needs a restart. `fsp dev` restarts by itself when `lib/app.g.dart` changed (`hot restart:
lib/app.g.dart changed`), but a change that only a restart picks up (a `const` that is read once, `main()`, `startup()`) needs `R`.
- **Nothing reloads when I save.** `hot_reload: false` in the pubspec, or a save outside `lib/`, or one the watcher ignores (it
  reads Dart files and folders under `lib/`); `r` always works. A save with an error in the routes sends nothing: the status line shows
  the first error, and `app.g.dart` is left as it was.
- **A `with` process is still running after `fsp dev` ended.** `fsp` stops each group (SIGTERM, then SIGKILL after 5 s; `taskkill /T /F` on
  Windows). It cannot after a SIGKILL of `fsp` itself: flutter sees the end of its stdin and stops, the `with` groups do not.
- **The terminal looks broken afterwards.** `fsp dev` puts it back when it ends or panics; `reset` fixes one it did not get the chance to.
- **`fsp telemetry` in `with`.** It starts its stack and returns, so it belongs in `before` (`before: fsp telemetry`), or press `t`.

## `fsp upgrade` (since 0.15.0)

`cli/src/upgrade.rs`; user documentation: [Upgrading fsp](https://github.com/fespalier/fespalier/blob/main/docs/getting-started.md#upgrading-fsp).
It needs no project. Printed to stderr, exit 1, unless noted; `--check` exits 3 (not 1) when an update exists.

| Message                                                                                                                          | Cause and fix                                                                                                                                                    |
| -------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `this fsp is the one `dart run fespalier` keeps for fespalier X; it follows the ref: in pubspec.yaml. ...`                       | The binary is the launcher's cached copy. Do not upgrade it: change the `ref:` of fespalier and every companion to the release you want, then `flutter pub get`. |
| `this fsp is a build of the source tree; ...`                                                                                    | A `target/debug` or `target/release` binary. Update the checkout and rebuild, or install a release.                                                              |
| `Homebrew installs only the release it has; to install vX.Y.Z run the install script with FSP_VERSION=vX.Y.Z set` (also `Scoop`) | `--version` on a package-manager install. Use the install script with `FSP_VERSION`, or drop `--version`.                                                        |
| `fsp upgrade needs `curl` on PATH to look up the latest release ...`                                                             | `curl` is missing. Install it (macOS, Linux and Windows 10+ include it), or run the install script.                                                              |
| `could not look up the latest release at URL: ...`                                                                               | No network, a proxy that `curl` does not see (`HTTPS_PROXY`), or a bad `FSP_RELEASES_URL`.                                                                       |
| `no release was found at URL` / `the latest release is tagged `X`, not vX.Y.Z`                                                   | The repository has no release yet, or its latest tag is not a plain `vX.Y.Z`. Pass `--version`.                                                                  |
| `--version wants a release tag like v1.2.3, not `X``                                                                             | Pre-release suffixes and non-versions are refused.                                                                                                               |
