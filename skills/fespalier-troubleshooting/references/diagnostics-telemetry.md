# Diagnostics: `fsp telemetry`, the stack and empty dashboards (since 0.8.0)

As of 0.8.0 (`cli/src/telemetry_stack.rs` for the command, `cli/templates/telemetry/openobserve/import.py` for the
importer). Messages are quoted as they are printed: the `fsp telemetry` ones from `fsp` (to stderr, exit 1), the
`fespalier:` ones from the `dashboards` container (`docker compose logs dashboards` in the stack folder, which is
`~/.fespalier/telemetry` unless `--dir` or `FSP_TELEMETRY_DIR` says otherwise), and the two OpenObserve lines from
OpenObserve itself. The user documentation is the README section
[Dashboards on your computer](https://github.com/vaam-apps/fespalier#dashboards-on-your-computer-fsp-telemetry);
the use is in `fespalier-testing`, `references/observability.md`.

## `fsp telemetry` says no

`{dir}` is the stack folder, `{code}` an exit code.

| Message                                                                                                                                                                                         | Cause and fix                                                                                                                                                                                                                             |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ``fsp telemetry needs Docker with Compose v2.20 or later: `docker compose version` failed ({error}). The stack's files are in {dir}; start them with `docker compose up -d` in that folder.``   | `docker` is not on `PATH` (`{error}` is `No such file or directory (os error 2)`) or its Compose plugin is missing. Install Docker; the files were written, so `docker compose up -d` in `{dir}` also works.                              |
| ``fsp telemetry needs Docker Compose v2.20 or later (for `docker compose wait`); this one is {version}``                                                                                        | Compose older than 2.20 has no `docker compose wait`. Update Docker.                                                                                                                                                                      |
| ``fsp telemetry needs a running Docker daemon: `docker info` failed ({error}). The stack's files are in {dir}; start Docker, then run `fsp telemetry` again.``                                  | Docker is installed but its daemon is not running (`{error}` is Docker's own, e.g. `failed to connect to the docker API at unix:///var/run/docker.sock; ...`). Start Docker Desktop, Colima or the service.                               |
| `docker compose up failed (exit {code}); its output is above. A port in use? Set FSP_OTLP_HTTP_PORT, FSP_OTLP_GRPC_PORT, FSP_O2_PORT or FSP_GRAFANA_PORT in {dir}/.env`                         | Read the output above it. Usually a port is taken (`failed to bind host port 127.0.0.1:4318/tcp: address already in use`; 3000 and 5080 are common): set the port in `.env`. Or an image could not be pulled (offline, a registry limit). |
| ``the dashboards were not imported into OpenObserve (exit {code}); `docker compose logs dashboards` in {dir} says why``                                                                         | The importer container failed. Run that command and look up its last line in the table below.                                                                                                                                             |
| `fsp telemetry can't find your home folder: pass --dir or set FSP_TELEMETRY_DIR`                                                                                                                | Neither `HOME` (`USERPROFILE` on Windows) nor `--dir` nor `FSP_TELEMETRY_DIR` is set (a CI job, a bare container).                                                                                                                        |
| `fsp telemetry --lan can't find this computer's address on your network; start without --lan and pass --dart-define=OTEL_EXPORTER_OTLP_ENDPOINT=http://<this computer's address>:4318 yourself` | The computer has no route to a network, so there is no address to give a phone. Connect, or pass the define by hand.                                                                                                                      |
| `can't write {path}: {io error}`                                                                                                                                                                | The stack folder is not writable (permissions, a file where a folder goes). Choose another `--dir`.                                                                                                                                       |
| `docker compose down failed (exit {code}); its output is above`                                                                                                                                 | `--stop` or `--reset` could not stop a container; the output above says which.                                                                                                                                                            |
| `there is no telemetry stack in {dir} (no compose.yaml): nothing to stop or reset`                                                                                                              | `--stop` or `--reset` in a folder `fsp telemetry` never wrote to. Pass the `--dir` it used.                                                                                                                                               |
| `error: the argument '--stop' cannot be used with '--grafana'`                                                                                                                                  | clap, exit 2. Also `'--stop'` with `'--reset'`, `'--lan'` with `'--reset'` and `'--no-start'` with `'--stop'`. `--stop`/`--reset` take only `--dir`; `--no-start` takes the rest.                                                         |

## The importer (`docker compose logs dashboards`)

The one-shot `dashboards` container loads the dashboards into OpenObserve on every `fsp telemetry`; it
exits 0 or 1. Each line starts with `fespalier:`, then:

| Line                                                                                                         | Meaning and fix                                                                                                                                                                                    |
| ------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `created the {traces\|logs} stream with {n} fields`                                                          | First run: the columns the panels name were created before any span arrived. Not a problem.                                                                                                        |
| `added {n} fields to the {traces\|logs} stream`                                                              | A newer `fsp` added columns to an existing stream. Not a problem.                                                                                                                                  |
| `{title}: created` / `{title}: updated` / `{title}: up to date`                                              | The dashboard was new, replaced by a newer version, or already current. The second run of `fsp telemetry` prints `up to date` six times.                                                           |
| `{title}: changed in OpenObserve since fsp telemetry wrote it, left alone; delete it to get the new version` | Someone edited the dashboard in OpenObserve and a newer `fsp` has a new version: yours is kept. Delete the dashboard in OpenObserve and run `fsp telemetry`.                                       |
| `OpenObserve did not answer at {url} within {seconds}s ({last error}).`                                      | Exit 1. OpenObserve is down or restarting. `docker compose logs openobserve`. The usual cause is the password line below. A slow machine can raise `FSP_O2_WAIT` (seconds, default 180) in `.env`. |
| `the {traces\|logs} stream: OpenObserve answered HTTP {status}: {body}`                                      | Exit 1. OpenObserve refused to create or read the stream; the body says why (a 401 is a wrong password: it was set on the first start, see below).                                                 |
| `could not create the fespalier folder: HTTP {status} {body}`                                                | Exit 1. As above, for the dashboard folder.                                                                                                                                                        |
| `could not list the fespalier dashboards: HTTP {status} {body}`                                              | Exit 1. As above.                                                                                                                                                                                  |
| `{title}: OpenObserve answered HTTP {status}: {body}`                                                        | Exit 1. OpenObserve rejected that dashboard (a 409 is a concurrent edit: run `fsp telemetry` again).                                                                                               |
| `OpenObserve stopped answering at {url}: {error}`                                                            | Exit 1. OpenObserve went away in the middle of the import. Run `fsp telemetry` again.                                                                                                              |

The OpenObserve container prints, and restarts for ever on:

```text
ZO_ROOT_USER_PASSWORD is too weak: Password must be 8-128 characters and contain at least one lowercase letter, one uppercase letter, one digit, and one special character.
```

`FSP_O2_PASSWORD` in `.env` is too weak. OpenObserve creates its root user on the **first start only**, so after
fixing `.env` run `fsp telemetry --reset` (it deletes the stack's data) and then `fsp telemetry`. The importer
meanwhile prints `OpenObserve did not answer at http://openobserve:5080 within 180s (<urlopen error [Errno -2] Name
does not resolve>).` and `fsp telemetry` the "dashboards were not imported" line.

## Symptoms

| Symptom                                                         | Cause                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **The dashboards are empty** (the App variable lists nothing)   | The app sends nothing to the collector. In order: telemetry is not switched on or installed in the app (the `telemetry: true` key and `FespalierTelemetry.install`, from fespalier's telemetry setup); a **web** app inside `otel_zone`'s `runGuarded` (it never runs its body: use `kIsWeb ? body() : observability.runGuarded(body)`); a **physical device** without `fsp telemetry --lan` and its `dart-defines.json`; a **release** build without `--dart-define=OTEL_EXPORTER_OTLP_ENDPOINT=...` (`FespalierOtel.endpoint()` is `''` there, so `otel_zone` leaves telemetry off); an endpoint on another port than 4318. |
| The Android emulator sends nothing                              | The endpoint is `localhost`, which is the emulator itself. `FespalierOtel.endpoint()` returns `10.0.2.2`; a hand-written endpoint must too.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| A web app is blocked by CORS                                    | Its origin is not `http://localhost:*` or `http://127.0.0.1:*`: set `FSP_OTLP_CORS_ORIGIN` in `.env` and run `fsp telemetry`. A page on `https` cannot post to `http://localhost` (mixed content): use `flutter run -d chrome`.                                                                                                                                                                                                                                                                                                                                                                                               |
| **A panel says `unknown field 'fespalier_...'`** in OpenObserve | The dashboards were imported before the stream had that column, from a pre-0.8.0 stack. Run `fsp telemetry` again: the importer adds the columns.                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Grafana shows **No data** where OpenObserve shows numbers       | Span metrics appear about 15 s after the spans (the collector flushes every 15 s), and Grafana panels over a short window can miss the newest ones. Wait, or widen the range.                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| A Grafana percentile differs from OpenObserve's                 | By design: Grafana interpolates within histogram buckets. Counts are the same.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| A changed OpenObserve password is not taken                     | The root user is created on the first start. `fsp telemetry --reset`, then `fsp telemetry`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
